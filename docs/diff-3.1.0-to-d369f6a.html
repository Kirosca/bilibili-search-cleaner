用户使用体感区别（v3.1.0 vs 当前版本）

1. 搜特殊字符不再卡死或搜偏

v3.1.0 体感：搜索 C++ 会变成 C ；搜 100% 等含百分号的词会直接报错中断过滤；含 !()* 的词可能因签名不一致导致请求异常。
当前版本体感：C++、100%、#Tag 及特殊符号均能原样识别，接口脱壳与本地过滤结果一致，不再报错中断。

2. 切换直播/番剧/专栏 Tab 不再误藏卡片

v3.1.0 体感：在视频页勾选【视频品质】筛选后切到直播、番剧等非视频 Tab，卡片可能被全部隐藏或沿用旧页缓存结果。
当前版本体感：品质筛选与品质栏严格限定仅在 综合(/all) 与 视频(/video) 生效，切换非视频 Tab 自动放行且不串用旧缓存。

3. 关闭“虚化过滤”后瀑布流继续正常补页

v3.1.0 体感：关闭虚化改为“直接隐藏”后，即使满屏大部分视频都被过滤掉了，瀑布流仍以为屏幕很满而不自动加载下一页。
当前版本体感：改为按实际可见高度计数，屏幕真实留存卡片不足 10 张时即自动抓取下一页补齐。

4. 中文输入法选词与页码跳转不再误触发重置

v3.1.0 体感：在页码框输数字按回车、或中文输入法敲回车选词时，可能误触发搜索重置或吸顶监听丢失。
当前版本体感：仅搜索框非输入法合成状态的回车才会触发同步，翻页/切路由防抖合并更稳，吸顶状态不会丢。

5. 综合页广告清理与弱网重试更稳

v3.1.0 体感：部分 /search/all 混合结果页首栏非视频时广告清理易漏网；断网重试按钮多次点击会重复绑事件；极少数异常卡标题可能显示 undefined。
当前版本体感：各分类逐一清理广告，重试按钮只响应一次点击，缺标题异常数据兜底为空白，课程卡也不再反复重扫卡顿。

核心差异对比详情

架构与路径收口

1. 瀑布流收口为 Vue 风格生命周期，并限定仅在视频搜索路径生效

c807f80 4d65e93 68a1240 5dc59bd a476e3c
v3.1.0 (bdae9a6)
  • 瀑布流仅简单判断 URL 含 keyword 参数，缺少统一挂载/卸载生命周期控制。
  • 品质筛选栏与 filterDOMElements() 过滤逻辑在非视频 Tab（如直播、番剧）下仍可能触发或隐藏全部卡片。
  • purifiedQuery 缓存键未包含 pathname，相同搜索词跨 Tab 切换会命中旧缓存。
当前版本 (d369f6a)
  • 建立清晰的挂载/暂停/重置生命周期控制器并补齐详细注释。
  • 引入 isVideoSearchPath()，统一将品质筛选栏与品质过滤限制在 /all 和 /video 路径。
  • 将 window.location.pathname 纳入 purifiedQuery 缓存键，彻底消除跨 Tab 缓存串扰。
请求与解码安全

2. 修复 URL 二次解码崩溃与 + 号破坏，补齐 Hash 兜底

de9998e 97ae900
v3.1.0 (bdae9a6)
  • 在 URLSearchParams.get('keyword') 已自动解码后，又重复执行 decodeURIComponent(rawParam.replace(/\+/g, ' '))。
  • 搜索 100% 等含 % 字符时抛出 URIError 导致过滤中断；搜索 C++ 时加号被误删为空格。
  • location.hash 解码无 try/catch，且 getCleanApiKeyword() 缺少 hash 兜底。
当前版本 (d369f6a)
  • 移除对 URLSearchParams.get() 返回值的二次 decodeURIComponent 与 + 替换，保留原始搜索词语义。
  • 为 window.location.hash 解码补充 try/catch 容错，畸形编码不再中断脚本执行。
  • 为 getCleanApiKeyword() 补齐 location.hash 拼接兜底，与本地语法提取保持一致。
请求与解码安全

3. fetch 拦截改写搜索词时同步重签 Wbi，并跳过内部已签名请求

df749f5
v3.1.0 (bdae9a6)
  • 拦截 /wbi/search 请求时仅正则替换 keyword 参数并采用 encodeURIComponent，未重算 w_rid / wts。
  • 连带二次改写脚本自身瀑布流已带 signWbi 签名的请求，特殊字符 [!'()*] 编码不一致会破坏签名校验。
当前版本 (d369f6a)
  • 识别并跳过脚本内部已签名请求（通过内部请求信号标记），避免二次改写。
  • 对页面原生发起的 Wbi 搜索请求在改写 keyword 后执行 signWbi 重签名，保障签名一致性。
交互与渲染健壮性

4. 修复初始化 TDZ 风险、关闭虚化后补页失效、SPA 防抖及输入法误触发

9b7b4de 6308dcf 7842c36 d369f6a 0fbaf88 2b592f9
v3.1.0 (bdae9a6)
  • 顶层同步调用 applyFilterStickyState()，若 DOM 已就绪可能提前访问未初始化的 const stickyObserver（TDZ）。
  • checkWaterfallFillScreen() 以 style.display !== 'none' 计数，关闭虚化用 CSS 隐藏卡片后补页失效。
  • 任意 INPUT 回车均触发重置（含页码输入框、中文输入法选词回车），SPA 路由延迟偏短。
  • showErrorLoader() 多次失败会叠加绑定多个 click 监听器；createCardElement() 标题无空值兜底。
当前版本 (d369f6a)
  • 延迟顶层 applyFilterStickyState() 执行，消除 TDZ 风险。
  • 补页计数改为 offsetHeight > 0，兼容 CSS 隐藏规则。
  • 收窄回车监听至搜索输入框并检查 !e.isComposing 与 e.target?.closest；scheduleRouteSync() 引入 pendingWithSticky 累加防丢失。
  • showErrorLoader() 清理/去重重试监听；createCardElement() 标题补充 || '' 兜底。
数据与缓存修复
