B站搜索净化器：手搓版核心演进与对比说明

相比最初的 3.0 发布版，当前手搓版（bilibili-search-cleaner-v2.1.0.user手搓.js）在视频品质打分体系、分区与流量动态校正、交互筛选体验以及大列表渲染性能四个方向进行了全面重构与增强。

01 · 新增功能
三层打分 + 20+ 词条

支持封面显性评分开关、样本较少筛选胶囊、卡片详尽 Tooltip 拆解。

02 · 规则与模型
分区感知 + 稀释补偿

引入播放稀释系数 playFactor、干货/娱乐分区阈值微调与低赞高藏直通。

03 · 修复与性能
增量 DOM + 二分视口

修复 Tooltip 截断，消除离屏重排，筛选切换与增量监听实现 O(1)/增量级响应。

一、新增功能

1. 杀戮尖塔风格「三层综合参考分」与封面显性评分开关

发布版仅展示品级名称；手搓版新增 SCORE_TIER_BANDS、computeScoreBreakdown 与 computeHealthScore，将评分拆解为 基础分 + 表现分 + 词条修正。

🏆 镇站之宝 · 95 💡 硬核干货 · 84 🌱 样本较少
① 品级基线（Base）

依据视频所处品级赋予区间基准分（如镇站之宝、硬核干货、高分口碑等），锁定品级天花板与保底线。

② 表现分拉伸（Performance）

采用 [perfFloor, perfCeil] 双端拉伸与非对称曲率（base ≥ 50 时曲率 1.15，低分段 0.90），拉开同品级内部差距。

③ 生态词条与显性开关

油猴二级菜单新增 └─ 封面显性评分: ✅ 已开启 / ❌ 已关闭（存储键 bili_cleaner_eval_score），通过根节点 bili-eval-score-enabled 类 O(1) 切换显示；🌱 样本较少 自动隐藏分数避免误导。

2. 20+ 互斥与生态结算词条（正向净加分上限 +12）

二、规则与模型调整

调整模块 3.0 发布版逻辑 手搓版改进逻辑
播放稀释补偿
playFactor		 无播放量对数补偿，高播放破圈视频易因路人稀释导致互动率偏低。 5 万播放以上引入对数稀释补偿，系数范围 1.0x ~ 1.40x，并在评分与部分阈值判定中参与校正。
⚠️ 谨慎观看 播放门槛 ≥ 20000 才触发低互动预警。 门槛下调至 ≥ 3000；新增 > 15 分钟 长视频兜底（点赞率 < 0.5% 且 收藏率 < 0.2%）；启用专属打分轨道（赞60% · 藏40%，noBonus: true，封顶 0~20 分）。
💡 硬核干货 固定藏赞比与互动率门槛，未区分分区类型与纯收藏不点赞习惯。 引入动态藏赞比 favLikeRatio（默认 ≥40%，干货分区/教程意图 30%，娱乐区 55%）；新增「低赞高藏直通车」（播放 ≥3000、收藏 ≥120、藏赞比 ≥75%、归一化收藏率 ≥2.5%×倍率）；阈值按分区乘 0.85x / 1.15x。
分区自适应
激辩 / 弹幕 / 默认轨 		全站使用统一热议/弹幕判定阈值与固定权重。 💬 激辩热议 在干货/教程分区采用 18% 辩论比门槛； 🔥 弹幕密集 在娱乐区提高 +15% 密度门槛；默认打分轨在干货区将 10% 弹幕权重转移至收藏（赞45% · 藏50% · 弹幕5%）。

三、Bug 修复与性能优化

Bug 修复

Tooltip 文本截断修复

修复内联 HTML 属性拼接导致的换行/特殊字符截断问题，改为通过 DOM 属性 newPill.title = tip 直接赋值，确保多行详情完整显示。

渲染优化

视口二分定位 + 滚动合并

updateViewportPage 改用 recomputeCardRows 配合对 cachedVisibleCards 的二分查找，消除 O(N) 离屏重排；checkAndTriggerPaging() 合入滚动 rAF 节流。

交互与监听

增量 MutationObserver & 筛选缓存

监听回调仅收集 addedNodes 并忽略脚本自身注入节点，移除重复统计调用；toggleQualityFilter 直接读取缓存的 dataset.qualityClass 与 dataset.syntaxPass，无需清空搜索状态全量重扫。

内存与计算

多处热路径缓存与有界 Map

  • 去重 computeQualityMetrics / getQualityQuadrant / renderBadgeColumn / cleanText 冗余调用。
  • toSimplified 增加纯 ASCII 快速通道；缓存 getSearchKeywords() URL 解析与 cachedWbiKeys.mixin_key。
  • fetch 拦截在未移除广告时直接透传；videoTagMap 与 videoStatMap 使用 setBoundedMap（上限 5000 条）防长会话内存泄漏。
